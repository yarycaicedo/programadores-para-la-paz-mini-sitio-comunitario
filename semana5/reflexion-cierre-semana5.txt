Respuesta: desde las primeras clases mi forma de trabajar cambió completamente. Antes no entendía para qué servía GitHub ni cómo organizar un repositorio, y ahora sé que la rama main es la base del proyecto que los docentes actualizan, mientras cada estudiante trabaja en su rama personal sin interferir con el proyecto base. Aprendí a usar git pull para traer cambios nuevos de forma ordenada, y cuando ocurre un fast-forward significa que la actualización fue limpia y sin conflictos. También entendí el valor de cada commit y cada push como evidencia real de mi trabajo. En la parte técnica pasé de escribir HTML y CSS básico a construir un mini-sitio con JavaScript, Node.js y Express que consume una API propia y entrega datos en formato JSON. Gracias a fetch, async y await el tablero de mensajes carga información dinámica desde el backend. Además aprendí que un README claro permite que otras personas entiendan y ejecuten el proyecto. El login pedagógico y el middleware simple me mostraron cómo funcionan las rutas protegidas. Pero lo más importante fue entender que la tecnología tiene un propósito comunitario: la difusión responsable, la revisión de fuentes, la consistencia comunicativa y el lenguaje responsable y no estigmatizante son la base para construir herramientas que fortalezcan la participación ciudadana y promuevan una cultura de paz.
