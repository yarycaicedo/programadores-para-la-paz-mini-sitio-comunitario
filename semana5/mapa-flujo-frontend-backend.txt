Completa el flujo con tus palabras.

1. Frontend

¿Qué parte del proyecto corresponde al frontend?

Respuesta:
El frontend corresponde a la parte visual que la persona usuaria ve y utiliza en el navegador. En este proyecto está compuesto por los archivos public/index.html, public/styles.css y public/app.js.

2. Backend

¿Qué parte del proyecto corresponde al backend?

Respuesta:
El backend corresponde a la parte que procesa solicitudes, lee los datos y responde información al frontend. En este proyecto está representado principalmente por server.js y los archivos de datos.

3. API propia

¿Qué rutas expone la API propia del proyecto?

Respuesta:
La API propia expone las rutas GET /api/mensajes, GET /api/calendario, GET /api/resumen, POST /api/login y GET /api/revision-editorial.

4. Datos

¿Qué archivos JSON usa el backend para responder?

Respuesta:
El backend utiliza los archivos data/mensajes.json y data/calendario-editorial.json para responder las solicitudes de la API.

5. Consulta desde frontend

¿Qué función de JavaScript se usa para consultar la API?

Respuesta:
Se utiliza la función fetch() para consultar las rutas de la API propia.

6. Espera de respuesta

¿Qué palabras se usan para esperar la respuesta del servidor?

Respuesta:
Se utilizan las palabras async y await para trabajar con respuestas asíncronas y esperar la información del servidor.

7. Conversión de respuesta

¿Qué hace respuesta.json()?

Respuesta:
respuesta.json() convierte la respuesta recibida desde la API en datos JavaScript que pueden ser utilizados por el frontend.

8. Render dinámico

¿Qué significa mostrar datos dinámicamente en el tablero?

Respuesta:
Significa que la información no está escrita directamente en el HTML, sino que se obtiene desde la API y JavaScript crea las tarjetas automáticamente cuando llegan los datos.

9. Prueba

¿Cómo verificaste que la información del tablero coincide con la API?

Respuesta:
Comparé los datos mostrados en las rutas JSON con la información presentada en las tarjetas del tablero y comprobé que coincidían. También modifiqué un mensaje en el archivo JSON y observé que el cambio apareció en el tablero después de reiniciar el servidor.

10. Propósito comunitario

¿Cómo ayuda esta integración a mantener información comunitaria actualizable?

Respuesta:
Esta integración permite actualizar la información desde los archivos de datos sin modificar manualmente la interfaz. Así la comunidad puede acceder a información organizada, actualizada, verificable y consistente de manera más eficiente.
